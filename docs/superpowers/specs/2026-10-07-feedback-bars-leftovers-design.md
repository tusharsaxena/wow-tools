# Bottom bars during a scan, one-press Leftovers: design

Date: 2026-10-07. Branch: `fix/feedback-2026-10-07-b`. Plan and ledger:
`../plans/2026-10-07-feedback-bars-leftovers.md`, `../plans/2026-10-07-feedback-bars-leftovers.status.md`.

User feedback 2026-10-07 (screenshots of the Ace3 Profile Manager): clicking Leftovers should first tick all leftover
characters, then remove them; and scanning or rescanning moves the action strip under the tree to the top of the
pane, when it should stay at the bottom, in every tool, as a standard.

## Decisions

| # | Topic | Decision |
|---|---|---|
| L1 | Leftovers (`o`) | Pressing Leftovers (button or `o`) first ticks every leftover character shown in the tree (the same set as More… → "Tick all leftover characters": what the View, the Show boxes and the `/` filter show; locked addons excluded as today), then opens the existing "Remove leftover characters?" confirm for exactly the ticked leftovers. With none shown it says "No leftover characters are shown." and changes nothing. Cancelling the confirm keeps the ticks (visible, so the user sees what would have gone). Help, guide, docs and CHANGELOG say so. |
| L2 | Bars stay at the bottom | While a scan (or anything else) stands in for a tree, the rows under the tree (the Ace3 guide and action bar, the SV Browser action bar, any future one) stay at the bottom of the pane: the shared `two_pane_css` gives `#scan-box` the tree's space (`height: 1fr`), so the stand-in fills the pane as the tree does. Applies to every two-pane screen through the shared CSS. |
| L3 | Standard | A new STD-7 MUST in `docs/standards.md`: a screen's bottom bars and button rows keep their position whatever stands in for the tree (scan progress, an empty or failed scan, a load); enforced by a test that scans every tool's review (and every two-pane screen with a scan box) and checks the rows under the tree and the left pane's button row sit at the same place during and after the scan. |
| L4 | Risk disclaimer | User feedback (screenshot of the SV Browser's USE AT YOUR OWN RISK popup): WTF Cleaner and Ace3 Profile Manager get the same kind of disclaimer, shown at most once per session. One shared disclaimer popup in `wowtools/ui/` (title, tool-specific text, Back (Esc) / I understand, I understand focused), shown after the flavor pick and before the first scan, at most once per tool per app session (remembered on the app; a Back does not count as seen, so it is asked again next time). The SV Browser keeps its text and moves to the shared popup and the once-per-session rule (this replaces its spec's D2 "each time the tool is opened"). Each tool logs its own accepted/declined events (registered; docs/events.md regenerated). Texts: honest about what each tool deletes or rewrites, that backups and Undo exist, and to close WoW first. Help, guides, README, CHANGELOG updated. |
| L5 | `t` on the pickers | The flavor and account picker screens (`ui/flavor_screen.py` and any other pre-review picker) bind `t` to go back to the tool menu, like every review and result screen; Esc keeps doing what it does today. The footer and hint name both (D17: no button carries `t`). Help and guides updated. |
| L6 | Nothing blocks before the scan box | User report 2026-10-08: the Screenshot Organizer takes ~5 s after the flavor pick with no indicator. The user's log shows 4.4 s between the flavor pick (08:35:00.605) and `shots.scan_started` (08:35:05.028) on the first open, then 0.13 s of scan; later opens were instant. The review's `on_mount` ran `validate_dest` (first touch of the destination drive `H:` in the session) and the Undo lookup on the UI thread before showing the scan box (STD-7.20). Fix: a review shows its scan box at once on mount; the destination check and the Undo lookup run in the scan worker (label "Checking the destination folder", then "Reading Screenshots folders"); a destination problem is still reported exactly as today. Every other tool's review mount and rescan is audited the same way; any disk access before the scan box moves into the worker. A test pins that the scan box is shown before any such check runs (a blocked check still leaves the scan box visible). |
| L7 | `q` quits from any screen | User feedback 2026-10-08: `q` does not work on the flavor picker. `q` becomes one app-wide binding (on the app, not per screen) that works on every screen and popup: the tool menu, the flavor and account pickers, reviews, result screens, settings, help, changelog, warnings, blacklist and every popup. Exceptions: while a text input has focus `q` types (the `/` filter, settings fields, name boxes); while a run is writing (`app.busy`) it does not quit and says why, as the reviews do today. Esc keeps its current meaning everywhere. A new STD-8 rule; a test presses `q` on every screen. |
| L8 | "Don't show this again" | User feedback 2026-10-08: the USE AT YOUR OWN RISK popup gets a checkbox "Don't show this warning again for this tool" (exact wording chosen by the implementer, short). Ticked and **I understand** saves `skip_risk_warning = true` in that tool's own config section (config/<tool>.cfg; a per-tool setting, every tool that shows the popup); Back never saves. `ask_disclaimer` skips the popup when the setting is true (on top of the once-per-session rule). Each tool's settings form gains a "Show the USE AT YOUR OWN RISK warning" checkbox to turn it back on if the form still fits at 120x30 (STD-7.23), else the guide explains the hand edit. Logged with a registered event; help, guides, README settings, CHANGELOG. |
| L9 | One toast anchor and stack | User feedback 2026-10-08 (screenshot: the Ace3 action tip and a "Not done" toast overlapping at different heights). Every toast on every screen starts from one shared anchor (bottom right, just above the screen's bottom bars and action bars) and several stack upward without overlapping; the Ace3 action tip (ActionTip in #tip-rack) joins that stack or always sits clear of it, so tips and toasts never overlap. One shared helper in `ui/` places them everywhere (reviews, restore screen, results, menu, pickers, popups). A new STD-7 rule; a test raises several toasts plus an action tip on every screen at 120x30 and 160x45 and checks one anchor and no overlap. |
| L10 | Long warning lists collapse | User feedback 2026-10-08 (screenshot: the Ace3 Dry run confirm lists 28 '"Default" does not exist yet' warnings as plain text, pushing Yes/No off the popup). In every confirm, notes and result popup, a list that can grow (warnings, notes, refusals, skipped items) is one collapsed, counted tree row ("⚠ 28 warnings (Space or click to expand)") whose children group by message, then where (flavor · account), then the items, so repeated sentences are shown once. Summary lines stay plain text above; the buttons always stay visible and the tree scrolls inside the popup. Built once in `ui/` (reusing the existing Notes tree pattern) and adopted by every tool. A new STD-7 rule; tests at 120x30 with 300 warnings keep the buttons on screen. |
