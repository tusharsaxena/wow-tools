## Decisions (settled with the user up front)

| # | Topic | Decision |
|---|---|---|
| D1 | Version | `__version__ = "0.1.0"` until the user tags 1.0.0. No tags or releases in this run. The README "1.0.0 First release" row and the "Unreleased" row fold into one `0.1.0` changelog entry. |
| D2 | Changelog | `CHANGELOG.md` at the repo root (Keep a Changelog: `## [X.Y.Z] - YYYY-MM-DD`, plus an optional `## [Unreleased]`), parsed by a UI-free `wowtools/core/changelog.py`. It replaces the README "Version History" table (README links to it). A test pins "`__version__` has an entry"; `scripts/build_release.py` refuses a tag with no entry; `docs/releasing.md` gets a "write the changelog entry" step before the release commit. |
| D3 | Changelog screen | Opened by `c` from the tool menu (footer key "Changelog"). Two panes in the suite look: versions on the left (OptionList, newest first, one per row, date beside it), the selected version's notes on the right (Markdown in a VerticalScroll). Esc/q back to the menu. |
| D4 | Version on the menu | A line under the banner art inside the banner area: `v0.1.0` (plus "· vX.Y.Z available, press u" when the updater knows of one). |
| D5 | BrandBar bug | `BrandBar` and `Footer` both `dock: bottom` and overlap, so the BrandBar has never been visible. Fix once in the shared UI (the version/update text shares the footer row, or the two are stacked in one bottom container), without costing a row that breaks the 120x30 layout tests. |
| D6 | Terms | Always-visible, muted, 1-2 line "Terms" text at the bottom of the tool menu (above the footer). No acceptance click. Same wording in README (and consistent with the MIT warranty clause). Wording: "Terms of use: Ka0s WoW Tools is provided as is, without warranty of any kind, and you use it at your own risk. Every tool backs up the files it changes before changing them, but keep your own backups of anything you can't afford to lose." |
| D7 | Tree filter | `/` focuses a "Filter" Input in the left pane of every tree screen (WTF review, Shots review, IB review, IB Restore, Ace3 review — reuses `#search` — and Ace3 Blacklist). Case-insensitive substring match on node labels (on model data, not rendered nodes, because children load lazily); matches' ancestors stay, matched groups auto-expand. Esc in the Input clears it and returns to the tree; Esc on the tree behaves as today. Space types into the Input. Popup detail trees are out of scope. |
| D8 | Select all / none | `a` / `n` (unchanged keys, same on every tickable screen) act on the items the filter shows only. The filter is a view: ticked items hidden by it stay ticked and still count toward the run. The summary line and the run's confirm both say "N selected items are hidden by the filter" when N > 0. Ace3 select-none changes to match (today it clears hidden ticks too). |
| D9 | Shared library | No new package: `wowtools/core/` (UI-free, never imports textual) and `wowtools/ui/` (Textual) are "the shared library", in-repo reusable code. Rule (CLAUDE.md, adding-a-tool.md, architecture.md): functionality two or more tools need lives in the shared library, never copied and never imported across tools. Extract the duplication listed in the library analysis (A1-A12, B1-B16) where it pays; pin single definitions in `tests/test_structure.py`; add a "core never imports textual" test. |
| D10 | Parallelism | `[general] parallelism` (int, default 2, range 1-8, `Config.parallelism`, edited on the setup screen). A shared `core/parallel.py` runner (ThreadPoolExecutor inside the existing single thread worker; one `activity.running()` around it so quit still waits). Applies to: Interface Backup "back up all", the read-only per-flavor scans (WTF multi-flavor scan, IB scanner, Shots/IB picker-count workers) and Ace3 undo snapshots. WTF Clean and Ace3 Apply stay serial (single crash markers, stop-on-first-failure). Journals, progress and logging must be thread-safe where shared. Document that slow disks (HDD, WSL `/mnt`) should use 1. |
| D11 | Progress popup | Fixed width and fixed height in every tool: title, an overall bar ("2 of 5 game versions"), one row per running unit (label, stage, bar) up to `parallelism`, sized to `min(parallelism, units)` at open and never resized; one-line ellipsised detail. Serial runs use the same box with one row. Bar fills its row (`Bar { width: 1fr }`). Progress updates are aggregated under a lock and pushed throttled. Fits 80x24 with 4 rows. |
| D12 | Action colours | Eight action kinds, theme variables in `ui/theme.py`, layered on the nearest Textual variant via a `-act-<kind>` class set by one helper (`action_button(kind=...)`), identical in every tool: destructive = red; overwrite/restore/organize/update = amber; safe-create/backup/save-copy = green; revert/undo = violet; simulate/dry run = cyan; confirm/save/primary go = blue; navigate (tools, other flavor, rescan, settings) = grey; cancel/back = dim grey. Staging buttons (Ace3 stage delete etc.) use the colour of the action they stage. Avoid clashing with WTF criterion colours: the destructive red is shared on purpose with the "Not installed" criterion (those are the files Clean deletes); the revert violet keeps at least 25 degrees of hue from the "stray copies" lavender (pinned). |
| D13 | Default Yes | Every `ConfirmScreen` focuses Yes (button order Yes, No). Safeguards: Yes takes the destructive colour when the action destroys or overwrites; Enter/Space on the popup are ignored for ~250 ms after mount. `y` / `n` / Esc unchanged. `LockScreen` keeps Quit as its default (Override bypasses the single-instance lock). `default_yes=` parameter goes away. |
| D14 | Dead code | Delete `InstallError` (`core/install.py`), `SNAPSHOT_NAME` and its now-unused `import re` (`wtf_cleaner/safety.py`), and the `ConfirmScreen` re-export in `wtf_cleaner/review_screen.py` (and its assertion). Pin in `test_dead_code_is_gone`. |
| D15 | Ace3 `u` | Ace3 review's `u` (unlock) shadows the app's `u` (update); once the BrandBar shows "press u to update" this misleads. The update hint on that screen must not say `u`, or the tool key moves; implementer decides, documented. |

## Out of scope
Cancelling a running job; parallel WTF Clean / Ace3 Apply; tags, releases, merge (separate approvals).
