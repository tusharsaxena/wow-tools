# Feedback round 2: WTF Cleaner

Branch `feat/wtf-cleaner-feedback-2`, stacked on `feat/wtf-cleaner-feedback-1`. The ledger is
`2026-10-03-feedback-2.status.md`.

## Findings that drive this round
- Dry run and clean sat at `--%` for about 30s. On a Windows drive under WSL, `Path.resolve()` costs about 13ms
  per SavedVariables file. Before the first progress report, the cleaner resolved every selected file three times
  (guard x2, backup x1) and stat'ed it twice.
- The snapshot's verify step (`testzip`) and the WTF folder walk reported no progress, and neither did the
  backup's preparation.
- The safety snapshot was removed straight after the delete loop, without checking the WTF folder against it.

## Tasks
1. **Cleaner: speed, stages, post-clean check.**
   - The guard resolves the account folder once and each parent folder once; a file that is a link falls back to a
     full resolve.
   - One `lstat` per file is shared by the guard and the recheck.
   - `BackupEntry` carries the size and mtime, so the backup stats nothing again; arcnames are computed lexically,
     with resolve only as a fallback.
   - `verify_backup` reads each entry (CRC) and reports progress.
   - The WTF listing uses `scandir` without stat calls.
   - Stages: `check`, `snapshot_list`, `snapshot`, `snapshot_verify`, `backup`, `verify`, `delete`, `validate`
     (total 0 means unknown).
   - After deleting, `check_clean` compares disk, snapshot and backup zip. Any problem keeps the snapshot
     (`snapshot.kept`, warning); success logs `clean.validated`. Either way the marker is cleared.
   - CLI stage lines and the result JSON are updated.
2. **Review UI.**
   - ←/→ switch panes; the button row lets → at its last button fall through to the tree.
   - Tree rebuild indicator: `loading` plus a summary line, a deferred and coalesced rebuild, labels built once, and
     a branch-only refresh on toggle.
   - Rescan button uses the warning variant.
   - Progress popup: stage titles for every stage, an indeterminate bar for unknown totals, and the file line fixed
     at 2 lines.
   - The results screen shows a kept snapshot and its problems.
3. **Docs.** Spec A.4/A.5/A.6/A.8, README, regenerated `docs/events.md`.
4. **Mid-build additions from the user.**
   - Logs per tool (`logs/<tool>/events-<date>.log`, `logfile-<date>.log`), with existing logs migrated.
   - Locked-file check before a real clean: a known-locker warning plus a per-file rename test.
