# WTF Cleaner: Feedback Round 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Apply the user's first round of hands-on feedback (spec Addendum A, §A.1–A.9) to the merged v0.1 code.

**Architecture:** Same layering as before. The logic changes go into the UI-free modules (`settings`, `scanner`, `rules`, `cleaner`, a new `safety` module, and `core/process`). The TUI changes stay in `wowtools/ui/*` and `wowtools/tools/wtf_cleaner/{app,review_screen}.py`, plus new screens.

**Tech Stack:** Python ≥ 3.10, vendored Textual 8.2.8, stdlib `unittest`.

**Spec:** `docs/superpowers/specs/2026-09-27-wtf-cleaner-design.md`. Read **Addendum A** first; it overrides earlier sections.

**How this plan differs from the v0.1 plan:** the code already exists, so each task gives the exact interfaces, the behaviour, and the **test cases that must exist and pass**. It doesn't give full code. Work test-first: write the listed tests, watch them fail, implement, watch them pass, then run the whole suite.

## Global Constraints

- Everything in the v0.1 plan's Global Constraints still applies:
  - Python 3.10 floor and `from __future__ import annotations`.
  - No `textual` import in `core/` or the tool logic modules.
  - Tests use `tests/fixtures.py` and never the real install or the network.
  - Every event is registered with a fixed level.
  - Commit messages end with the two trailer lines.
- Branch: `feat/wtf-cleaner-feedback-1`. Ledger: `docs/superpowers/plans/2026-09-27-feedback-1.status.md`, updated in the same commit as each task.
- Full suite: `python3 -m unittest discover -s tests -t .`. It must be green before every commit.
- After changing any event registry, regenerate `docs/events.md` with `python3 scripts/gen_event_docs.py`. `tests/test_docs.py` enforces this.
- Never auto-restore after a crash (§A.4.5).

## Review Focus

1. **The safety snapshot must never cause data loss.**
   - If the snapshot fails, nothing is deleted.
   - Restoring after an error puts back only files this run deleted, and never overwrites a file that exists on disk.
   - A failed restore keeps the marker and the snapshot.
2. **Scoped scans.** A scoped account's "not enabled" result must come from that account's characters only. "All accounts" must stay identical to v0.1.
3. **Keyboard navigation.** Arrow bindings must not steal keys from the tree, lists, tables or inputs while they have focus.
4. **Progress callbacks.** They run in worker threads, so UI updates must go through `call_from_thread`. A callback that raises must not break a clean.
5. **Process-path matching.** Paths differ in case and in separators (`\` vs `/`), and they may be missing (`None`).

### Task 5: Safety snapshot, crash recovery and clean progress (§A.4, §A.5 clean half)

**Files:**
- New `wowtools/tools/wtf_cleaner/safety.py`.
- `wowtools/tools/wtf_cleaner/cleaner.py`, `wowtools/tools/wtf_cleaner/events.py`, `wowtools/tools/wtf_cleaner/cli.py`, `wowtools/tools/wtf_cleaner/report.py`.
- `docs/events.md`.
- Tests: new `tests/test_safety.py`, `tests/test_cleaner.py`, `tests/test_wtf_cli.py`.

**Interfaces (`safety.py`, UI-free):**
- Constants: `MARKER_NAME = "clean-in-progress.json"`, `SNAPSHOT_PREFIX = "wtf-snapshot"`.
- `@dataclass(frozen=True) class Marker` with fields `snapshot: Path`, `flavor: str`, `flavor_path: Path`, `started: str`, `pid: int`, `suite_version: str`, `files: list[str]`.
- `take_snapshot(flavor, backup_dir, now, progress=None) -> Path`. It zips every regular file under `flavor.wtf_dir`, storing entries relative to `flavor.path` (`WTF/...`), and verifies the zip using `core.backup.verify_backup` with the expected sizes. It writes to `.partial` and then renames. On any failure it raises `BackupError`. Progress calls use stage `"snapshot"`.
- `write_marker(backup_dir, marker)`, `read_marker(backup_dir) -> Marker | None` (`None` if the file is missing or unreadable, and it never raises), `clear_marker(backup_dir)`.
- `restore_deleted(snapshot: Path, flavor, rel_paths: list[str]) -> list[str]` extracts exactly those entries into `flavor.path`. It skips any path that exists on disk (it never overwrites). It raises `BackupError` if the snapshot can't be read. It returns the paths it restored.
- `recovery_message(marker) -> str` is the shared text for the TUI and the CLI. It says the last clean didn't finish, when it started, where the snapshot is, and "close WoW, then unzip it into <flavor_path> to restore".

**`execute()` changes:**
- Signature: `execute(items, flavor, *, dry_run, backup, backup_dir, now=None, progress: CleanProgress | None = None) -> CleanResult`, where `CleanProgress = Callable[[str, int, int, str], None]` takes `(stage, current, total, detail)`.
- Stages, in order:
  1. The guard and the recheck, as before.
  2. **Real clean only:** `take_snapshot` (stage `snapshot`), then `write_marker` with the files to delete. A snapshot failure raises `BackupError` before anything is deleted.
  3. The selective backup (stage `backup`, one call per file). This also runs in a dry run.
  4. `verify` (one call).
  5. `delete` (one call per file). A dry run reports would-delete here.
- **Deleting loop:**
  - A per-file `OSError` gives a `failed` outcome, as before.
  - Any **other** exception (including `KeyboardInterrupt`) triggers `restore_deleted(snapshot, flavor, deleted_so_far)`. On success it emits `restore.completed`, clears the marker and raises `CleanError(f"Clean stopped ({exc}); {n} deleted files were restored from {snapshot}")`. If the restore itself fails, it emits `restore.failed`, **keeps** the marker and the snapshot, and raises `CleanError` naming the snapshot.
- **On completion** (including per-file failures): delete the snapshot file, `clear_marker`, and emit `snapshot.removed`.
- **Callbacks:** progress calls are wrapped. An exception raised by the callback is ignored, and must not trigger a restore.
- `CleanResult` gains `snapshot_path: Path | None` (the snapshot used; it's already removed by the time the result is returned) and `restored: list[str]`.

**New events (register them and regenerate the docs):**

| Event | Level |
|---|---|
| `snapshot.created` | info |
| `snapshot.removed` | info |
| `snapshot.failed` | error |
| `restore.completed` | warning |
| `restore.failed` | error |
| `recovery.incomplete_clean` | warning |

**CLI:**
- At startup, before scanning, if `read_marker(resolved_backup_dir)` finds a marker, print `recovery_message` to stderr and emit `recovery.incomplete_clean`, then continue. The marker is not removed; only the TUI's Dismiss removes it.
- During `--clean` without `--json`, print one line per stage change: "Taking safety snapshot…", "Writing backup…", "Deleting…". The output must not flood the terminal: stage changes only, no per-file lines.

**Tests (`tests/test_safety.py` and `tests/test_cleaner.py`):**
- `test_snapshot_contains_whole_wtf_and_verifies`: every file under `_retail_/WTF` is in the zip, including `config-cache.wtf` and `AddOns.txt`.
- `test_marker_round_trip_and_unreadable_marker_returns_none`.
- `test_restore_deleted_never_overwrites`: a file recreated on disk is left alone, and only missing files are restored.
- `test_clean_success_removes_snapshot_and_marker`: afterwards `backup_dir` has only the selective zip. Events include `snapshot.created` and `snapshot.removed`.
- `test_snapshot_failure_deletes_nothing`: patch `take_snapshot` to raise `BackupError`. All files are still present, and no marker is left.
- `test_unexpected_error_mid_delete_restores_deleted_files`: patch `Path.unlink` so the 4th call raises `RuntimeError`. The 3 deleted files are back with identical bytes, the marker is gone, `CleanError` mentions "restored", and the event `restore.completed` fires.
- `test_keyboard_interrupt_mid_delete_restores`: the same with `KeyboardInterrupt`.
- `test_restore_failure_keeps_marker_and_snapshot`: patch `restore_deleted` to raise. The marker and the snapshot both exist, and `CleanError` names the snapshot path.
- `test_dry_run_takes_no_snapshot`.
- `test_progress_stages_in_order`: stages seen are `snapshot` → `backup` → `verify` → `delete`, each stage's final call has `current == total`, and a callback that raises changes nothing.
- CLI: with a marker file present in the backup folder, a read-only run prints "did not finish" to stderr and exits 0.

**Commit:** `feat(wtf-cleaner): safety snapshot, interrupted-clean recovery notice, clean progress callbacks`

### Task 6: WoW running check per flavor (§A.9)

**Files:** `wowtools/core/process.py`, `tests/test_process.py`, and the callers in `review_screen.py` and `cli.py`.

**Interfaces:**
- `@dataclass(frozen=True) class WowProcess` with fields `name: str` and `path: str | None`.
- `running_wow_processes(*, platform: str | None = None, runner=subprocess.run, proc_root=Path("/proc")) -> list[WowProcess] | None`. `platform` is one of `"windows"`, `"wsl"`, `"linux"` or `"mac"`, and is auto-detected when `None`.
  - **Windows and WSL:** run `powershell.exe` (`powershell` on Windows) with `-NoProfile -NonInteractive -Command` and a `Get-CimInstance Win32_Process` query filtered to the four executable names, printing `Name|ExecutablePath` per line, with a 10 s timeout. If that fails, fall back to the existing `tasklist` parse with `path=None`.
  - **Linux:** for each `/proc/<pid>/cmdline` whose first NUL-separated argument's basename (split on both `/` and `\`) matches a WoW executable, record that argument as the path.
  - **Mac:** return `None`.
- `processes_for_flavor(processes, flavor_folder) -> tuple[list[WowProcess], list[WowProcess]]` returns `(matching, unknown)`. A process matches when the parent-folder component of its path, split on both separators and compared case-insensitively, equals `flavor_folder`. `unknown` holds the processes with `path=None`.
- `wow_check_for(flavor) -> Callable[[], list[str] | None]`, the callable the review screen and CLI use. It returns display strings: `"WowB.exe"` for matches and `"WowClassic.exe (flavor unknown)"` for unknown paths. It returns `None` when the check can't run. Replace the old `running_wow_executables` usage, but keep the function for compatibility.

**Tests:**
- Parsing PowerShell output: `"WowB.exe|G:\\Games\\Blizzard\\World of Warcraft\\_classic_beta_\\WowB.exe\r\n"` gives `path` ending in `_classic_beta_\WowB.exe`.
- Matching: that process matches `_classic_beta_` but not `_classic_era_`. `/home/u/Games/wow/_retail_/Wow.exe` matches `_retail_`. `path=None` goes into `unknown`.
- A PowerShell failure (the runner raises) falls back to tasklist output with `path=None`.
- Linux: a fake `/proc/123/cmdline` of `Z:\\wow\\_retail_\\Wow.exe\x00-arg` gives a path, and it matches `_retail_`.
- `wow_check_for`: WowB.exe running while `_retail_` is chosen gives `[]`.

**Commit:** `feat(core): flavor-aware WoW running check using executable paths`
